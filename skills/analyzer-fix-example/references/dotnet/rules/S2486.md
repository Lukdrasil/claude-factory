# S2486: Generic exceptions should not be ignored

**Analyzer**: SonarAnalyzer.CSharp · **Kit config**: not configured; on by default (Sonar way) · **Docs**: https://rules.sonarsource.com/csharp/RSPEC-2486/

## Wrong

```csharp
namespace Kit.Notifications.Infrastructure.Email;

internal sealed class EmailSender
{
    public async Task SendAsync(string to, string body, CancellationToken cancellationToken)
    {
        try
        {
            await DispatchAsync(to, body, cancellationToken);
        }
        catch (Exception) // Noncompliant: swallowed silently
        {
        }
    }

    private Task DispatchAsync(string to, string body, CancellationToken cancellationToken) =>
        Task.CompletedTask;
}
```

## Right

```csharp
using Microsoft.Extensions.Logging;

namespace Kit.Notifications.Infrastructure.Email;

internal sealed class EmailSender(ILogger<EmailSender> logger)
{
    public async Task SendAsync(string to, string body, CancellationToken cancellationToken)
    {
        try
        {
            await DispatchAsync(to, body, cancellationToken);
        }
        catch (Exception ex)
        {
            logger.LogError(ex, "Email dispatch to {Recipient} failed", to);
        }
    }

    private Task DispatchAsync(string to, string body, CancellationToken cancellationToken) =>
        Task.CompletedTask;
}
```

**Principle**: An empty `catch (Exception)` turns a failed send into silent success, nothing in the logs, nothing in the return value, so the next person to investigate a missing email has no trace to start from; logging the exception keeps the failure visible even though the method still swallows it by design.
