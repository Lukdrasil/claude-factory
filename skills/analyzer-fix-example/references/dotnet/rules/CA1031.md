# CA1031: Do not catch general exception types

**Analyzer**: Microsoft.CodeAnalysis.NetAnalyzers · **Kit config**: suggestion · **Docs**: https://learn.microsoft.com/en-us/dotnet/fundamentals/code-analysis/quality-rules/ca1031

## Wrong

```csharp
namespace Kit.Modules.Orders.Application.Features.ImportOrders;

internal interface IOrderRepository
{
    Task BulkInsertAsync(Stream file, CancellationToken ct);
}

internal sealed class ImportOrdersHandler(IOrderRepository repository)
{
    public async Task<bool> ImportAsync(Stream file, CancellationToken ct)
    {
        try
        {
            await repository.BulkInsertAsync(file, ct);
            return true;
        }
        catch (Exception) // swallows every failure, including bugs
        {
            return false;
        }
    }
}
```

## Right

```csharp
namespace Kit.Modules.Orders.Application.Features.ImportOrders;

internal interface IOrderRepository
{
    Task BulkInsertAsync(Stream file, CancellationToken ct);
}

internal sealed class OrderImportException(string message) : Exception(message);

internal sealed class ImportOrdersHandler(IOrderRepository repository)
{
    public async Task<bool> ImportAsync(Stream file, CancellationToken ct)
    {
        try
        {
            await repository.BulkInsertAsync(file, ct);
            return true;
        }
        catch (IOException)
        {
            return false;
        }
        catch (OrderImportException)
        {
            return false;
        }
    }
}
```

**Principle**: Catching only the exception types the caller can meaningfully recover from keeps unexpected failures (null refs, logic bugs) visible instead of silently turned into a `false` return.
