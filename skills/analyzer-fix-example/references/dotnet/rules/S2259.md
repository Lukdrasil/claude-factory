# S2259: Null pointers should not be dereferenced

**Analyzer**: SonarAnalyzer.CSharp · **Kit config**: not configured; on by default (Sonar way) · **Docs**: https://rules.sonarsource.com/csharp/RSPEC-2259/

## Wrong

```csharp
namespace Kit.Customers.Features.GetCustomerEmail;

internal sealed record CustomerProfile(string Email);

internal sealed class GetCustomerEmailHandler
{
    public string Handle(CustomerProfile? profile)
    {
        if (profile is null)
        {
            // logged elsewhere, falls through
        }

        return profile.Email; // Noncompliant: profile can be null here
    }
}
```

## Right

```csharp
namespace Kit.Customers.Features.GetCustomerEmail;

internal sealed record CustomerProfile(string Email);

internal sealed class GetCustomerEmailHandler
{
    public string Handle(CustomerProfile? profile) =>
        profile switch
        {
            null => string.Empty,
            { Email: var email } => email
        };
}
```

**Principle**: The `if (profile is null)` branch proves the author knew `profile` could be null, then fell through to dereference it anyway; a pattern-matching switch makes the null case an exhaustive, compiler-checked branch instead of a comment-and-hope.
