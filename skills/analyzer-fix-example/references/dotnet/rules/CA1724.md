# CA1724: Type names should not match namespaces

**Analyzer**: Microsoft.CodeAnalysis.NetAnalyzers · **Kit config**: suggestion, in Contracts folders · **Docs**: https://learn.microsoft.com/en-us/dotnet/fundamentals/code-analysis/quality-rules/ca1724

## Wrong

```csharp
namespace Kit.Modules.Billing.Application.Contracts;

public sealed record Billing(Guid Id, decimal Amount); // matches the "Kit.Modules.Billing" namespace
```

## Right

```csharp
namespace Kit.Modules.Billing.Application.Contracts;

public sealed record BillingSummary(Guid Id, decimal Amount);
```

**Principle**: A contract type named identically to its own module's namespace forces every caller to fully qualify or alias it to disambiguate, so a more specific name removes the ambiguity for free.

**Layer note**: The kit enables CA1724 specifically for Application/Contracts; public DTOs are the types external callers reference by name, where a namespace collision is most disruptive. Internal types in other folders are not flagged.
