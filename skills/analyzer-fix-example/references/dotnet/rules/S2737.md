# S2737: "catch" clauses should do more than rethrow

**Analyzer**: SonarAnalyzer.CSharp · **Kit config**: not configured; on by default (Sonar way) · **Docs**: https://rules.sonarsource.com/csharp/RSPEC-2737/

## Wrong

```csharp
namespace Kit.Payments.Infrastructure.Gateway;

internal sealed class PaymentGatewayClient
{
    public async Task<string> ChargeAsync(decimal amount, CancellationToken cancellationToken)
    {
        try
        {
            return await SendAsync(amount, cancellationToken);
        }
        catch (HttpRequestException) // Noncompliant: adds nothing, just rethrows
        {
            throw;
        }
    }

    private Task<string> SendAsync(decimal amount, CancellationToken cancellationToken) =>
        Task.FromResult("ok");
}
```

## Right

```csharp
namespace Kit.Payments.Infrastructure.Gateway;

internal sealed class PaymentGatewayClient
{
    public Task<string> ChargeAsync(decimal amount, CancellationToken cancellationToken) =>
        SendAsync(amount, cancellationToken);

    private Task<string> SendAsync(decimal amount, CancellationToken cancellationToken) =>
        Task.FromResult("ok");
}
```

**Principle**: A `catch` that only calls `throw;` has the exact same runtime effect as no `catch` at all, but costs a reader time deciding whether it was supposed to do something; removing it (or, when the intent was real, adding the logging/wrapping that justifies catching) makes the code say what it means.
