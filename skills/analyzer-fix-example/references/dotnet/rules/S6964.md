# S6964: Value type property used as input in a controller action should be nullable, required or annotated with the JsonRequiredAttribute to avoid under-posting

**Analyzer**: SonarAnalyzer.CSharp · **Kit config**: not configured; on by default (Sonar way) · **Docs**: https://rules.sonarsource.com/csharp/RSPEC-6964/

## Wrong

```csharp
namespace Kit.Orders.Controllers;

internal sealed record CreateOrderRequest
{
    public int Quantity { get; init; } // Noncompliant: omitted field silently binds to 0
    public decimal UnitPrice { get; init; } // Noncompliant
}

[ApiController]
[Route("orders")]
internal sealed class OrdersController : ControllerBase
{
    [HttpPost]
    public IActionResult Create(CreateOrderRequest request) => Ok();
}
```

## Right

```csharp
namespace Kit.Orders.Controllers;

internal sealed record CreateOrderRequest
{
    public required int Quantity { get; init; }
    [JsonRequired] public decimal UnitPrice { get; init; }
}

[ApiController]
[Route("orders")]
internal sealed class OrdersController : ControllerBase
{
    [HttpPost]
    public IActionResult Create(CreateOrderRequest request) => Ok();
}
```

**Principle**: an omitted `int`/`decimal` field binds to its zero default, making "the client didn't send it" indistinguishable from "the client sent zero"; which can silently grant a default role, quantity or price; mark the property `required` (or `[JsonRequired]`) so a missing field fails model binding instead of passing through as a false value.

**Layer note**: kit slice request/command records bind through the same System.Text.Json model binder in minimal APIs, so apply the same `required`/`JsonRequired` guard there too, not only on MVC controller input models.
