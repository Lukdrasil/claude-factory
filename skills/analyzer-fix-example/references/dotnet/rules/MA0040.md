# MA0040: Forward the CancellationToken parameter to methods that take one

**Analyzer**: Meziantou.Analyzer · **Kit config**: not configured; analyzer default: Info · **Docs**: https://github.com/meziantou/Meziantou.Analyzer/blob/main/docs/Rules/MA0040.md

## Wrong

```csharp
namespace Kit.Orders.Application.Features.PlaceOrder;

internal interface IOrderRepository
{
    Task SaveAsync(Order order, CancellationToken cancellationToken = default);
}

public sealed record Order(Guid Id);

internal sealed class OrderPlacer(IOrderRepository repository)
{
    public async Task PlaceAsync(Order order, CancellationToken cancellationToken)
    {
        await repository.SaveAsync(order); // MA0040: token not forwarded
    }
}
```

## Right

```csharp
namespace Kit.Orders.Application.Features.PlaceOrder;

internal interface IOrderRepository
{
    Task SaveAsync(Order order, CancellationToken cancellationToken = default);
}

public sealed record Order(Guid Id);

internal sealed class OrderPlacer(IOrderRepository repository)
{
    public async Task PlaceAsync(Order order, CancellationToken cancellationToken)
    {
        await repository.SaveAsync(order, cancellationToken);
    }
}
```

**Principle**: A CancellationToken that is already in scope but not passed down leaves the downstream call unable to observe cancellation, so a caller's cancel request has no effect until the whole chain finishes on its own; forwarding it lets cancellation propagate all the way to the repository call.
