# S1448: Classes should not have too many methods

**Analyzer**: SonarAnalyzer.CSharp · **Kit config**: warning in Domain · **Docs**: https://rules.sonarsource.com/csharp/RSPEC-1448/

## Wrong

```csharp
namespace Kit.Catalog.Domain;

public sealed class Product // too many methods on one aggregate
{
    public void Rename(string name) { }
    public void Reprice(Money price) { }
    public void Discontinue() { }
    public void Restock(int quantity) { }
    public void ReserveStock(int quantity) { }
    public void ReleaseReservation(int quantity) { }
    public void AddReview(CustomerId customerId, int rating) { }
    public void RemoveReview(ReviewId reviewId) { }
    public void FlagReviewAsSpam(ReviewId reviewId) { }
    public void Tag(string tag) { }
    public void Untag(string tag) { }
    public void AttachImage(Uri imageUrl) { }
    // ... twenty-five more methods spanning pricing, inventory and reviews
}
```

## Right

```csharp
namespace Kit.Catalog.Domain;

public sealed class Product
{
    public void Rename(string name) { }
    public void Reprice(Money price) { }
    public void Discontinue() { }
    public void Tag(string tag) { }
    public void Untag(string tag) { }
    public void AttachImage(Uri imageUrl) { }

    public ProductInventory Inventory { get; } = new();
    public ProductReviews Reviews { get; } = new();
}

public sealed class ProductInventory
{
    public void Restock(int quantity) { }
    public void Reserve(int quantity) { }
    public void ReleaseReservation(int quantity) { }
}

public sealed class ProductReviews
{
    public void Add(CustomerId customerId, int rating) { }
    public void Remove(ReviewId reviewId) { }
    public void FlagAsSpam(ReviewId reviewId) { }
}
```

**Principle**: A large method count on one class is evidence it has taken on several responsibilities (identity, inventory, reviews); splitting the methods that share state into their own types shrinks each type's public surface to the one responsibility it owns.
