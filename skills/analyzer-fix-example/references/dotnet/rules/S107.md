# S107: Methods should not have too many parameters

**Analyzer**: SonarAnalyzer.CSharp · **Kit config**: suggestion in Features · **Docs**: https://rules.sonarsource.com/csharp/RSPEC-107/

## Wrong

```csharp
namespace Kit.Orders.Features.PlaceOrder;

internal sealed class PlaceOrderHandler
{
    public OrderId Handle(
        CustomerId customerId,
        string sku,
        int quantity,
        string currency,
        decimal unitPrice,
        string shippingStreet,
        string shippingCity,
        string shippingPostalCode) // too many parameters
    {
        return OrderId.New();
    }
}
```

## Right

```csharp
namespace Kit.Orders.Features.PlaceOrder;

internal sealed record ShippingAddress(string Street, string City, string PostalCode);

internal sealed record PlaceOrderCommand(
    CustomerId CustomerId,
    string Sku,
    int Quantity,
    Money UnitPrice,
    ShippingAddress ShippingAddress);

internal sealed class PlaceOrderHandler
{
    public OrderId Handle(PlaceOrderCommand command) => OrderId.New();
}
```

**Principle**: Eight positional parameters force every caller to track argument order by memory; grouping the ones that always travel together (address fields, money fields) into a command/value object makes the call self-describing and impossible to misorder.
