# CA1860: Avoid using 'Enumerable.Any()' extension method

**Analyzer**: Microsoft.CodeAnalysis.NetAnalyzers · **Kit config**: not configured; enabled by default as a suggestion (Info) in the .NET 10 SDK; an IDE-only hint, does not fail a warnings-as-errors build unless raised in `.editorconfig` · **Docs**: https://learn.microsoft.com/en-us/dotnet/fundamentals/code-analysis/quality-rules/ca1860

## Wrong

```csharp
namespace Kit.Modules.Orders.Application.Features.SubmitOrder;

internal sealed record OrderLine(string Sku, int Quantity);

internal sealed class SubmitOrderValidator
{
    public bool HasLines(IReadOnlyList<OrderLine> lines) => lines.Any(); // Count is available, Any() still used
}
```

## Right

```csharp
namespace Kit.Modules.Orders.Application.Features.SubmitOrder;

internal sealed record OrderLine(string Sku, int Quantity);

internal sealed class SubmitOrderValidator
{
    public bool HasLines(IReadOnlyList<OrderLine> lines) => lines.Count > 0;
}
```

**Principle**: `Any()` on a collection that already exposes `Count`/`Length`/`IsEmpty` allocates and advances an enumerator just to answer a question the property already answers in O(1).
