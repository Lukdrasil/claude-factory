# IDE0290: Use primary constructor

**Analyzer**: IDE built-in · **Kit config**: preferred in Features (warning) · none in Domain · **Docs**: https://learn.microsoft.com/en-us/dotnet/fundamentals/code-analysis/style-rules/ide0290

## Wrong

```csharp
namespace Acme.Features.Orders;

internal interface IOrderRepository
{
    void Save(int orderId);
}

internal sealed class CancelOrderHandler // marker: verbose ctor instead of primary ctor
{
    private readonly IOrderRepository _repository;

    public CancelOrderHandler(IOrderRepository repository)
    {
        _repository = repository;
    }

    public void Handle(int orderId) => _repository.Save(orderId);
}
```

## Right

```csharp
namespace Acme.Features.Orders;

internal interface IOrderRepository
{
    void Save(int orderId);
}

internal sealed class CancelOrderHandler(IOrderRepository repository)
{
    public void Handle(int orderId) => repository.Save(orderId);
}
```

**Principle**: a primary constructor drops the field-plus-assignment boilerplate for a class whose only job is to hold its injected dependencies, keeping the slice's handler short.

**Layer note**: preferred in Features (primary constructors keep slices short); avoided in Domain (captured parameters cannot be readonly); use a classic constructor on entities.
