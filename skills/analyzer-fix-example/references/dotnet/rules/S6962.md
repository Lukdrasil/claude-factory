# S6962: You should pool HTTP connections with HttpClientFactory

**Analyzer**: SonarAnalyzer.CSharp · **Kit config**: not configured; on by default (Sonar way) · **Docs**: https://rules.sonarsource.com/csharp/RSPEC-6962/

## Wrong

```csharp
namespace Kit.Payments.Infrastructure;

internal sealed class PaymentGatewayAdapter
{
    public async Task<bool> ChargeAsync(decimal amount, CancellationToken cancellationToken)
    {
        using var client = new HttpClient(); // Noncompliant: bypasses pooled connections
        HttpResponseMessage response = await client.PostAsync(
            "https://payments.example.com/charge",
            JsonContent.Create(amount),
            cancellationToken);
        return response.IsSuccessStatusCode;
    }
}
```

## Right

```csharp
namespace Kit.Payments.Infrastructure;

internal sealed class PaymentGatewayAdapter(IHttpClientFactory httpClientFactory)
{
    public async Task<bool> ChargeAsync(decimal amount, CancellationToken cancellationToken)
    {
        using HttpClient client = httpClientFactory.CreateClient(nameof(PaymentGatewayAdapter));
        HttpResponseMessage response = await client.PostAsync(
            "https://payments.example.com/charge",
            JsonContent.Create(amount),
            cancellationToken);
        return response.IsSuccessStatusCode;
    }
}
```

**Principle**: `new HttpClient()` per call opens a socket that lingers in TIME_WAIT after disposal, exhausting available sockets under load; resolve clients from `IHttpClientFactory` (registered once via `AddHttpClient` in the composition root) so connections are pooled and reused.

**Layer note**: applies to Infrastructure adapters that call outbound HTTP; Domain and Application never construct an `HttpClient` directly.
