# S6967: ModelState.IsValid should be called in controller actions

**Analyzer**: SonarAnalyzer.CSharp · **Kit config**: not configured; on by default (Sonar way) · **Docs**: https://rules.sonarsource.com/csharp/RSPEC-6967/

## Wrong

```csharp
using Microsoft.EntityFrameworkCore;

namespace Kit.Orders.Controllers;

internal sealed record CreateOrderRequest(int Quantity);
internal sealed class Order { public int Quantity { get; init; } }
internal sealed class OrderDbContext : DbContext { public DbSet<Order> Orders => Set<Order>(); }

internal sealed class OrdersController(OrderDbContext dbContext) : Controller
{
    [HttpPost]
    public async Task<IActionResult> Create(CreateOrderRequest request, CancellationToken cancellationToken)
    {
        dbContext.Orders.Add(new Order { Quantity = request.Quantity }); // Noncompliant: ModelState never checked
        await dbContext.SaveChangesAsync(cancellationToken);
        return RedirectToAction(nameof(Index));
    }

    public IActionResult Index() => View();
}
```

## Right

```csharp
using Microsoft.EntityFrameworkCore;

namespace Kit.Orders.Controllers;

internal sealed record CreateOrderRequest(int Quantity);
internal sealed class Order { public int Quantity { get; init; } }
internal sealed class OrderDbContext : DbContext { public DbSet<Order> Orders => Set<Order>(); }

internal sealed class OrdersController(OrderDbContext dbContext) : Controller
{
    [HttpPost]
    public async Task<IActionResult> Create(CreateOrderRequest request, CancellationToken cancellationToken)
    {
        if (!ModelState.IsValid)
        {
            return View(request);
        }

        dbContext.Orders.Add(new Order { Quantity = request.Quantity });
        await dbContext.SaveChangesAsync(cancellationToken);
        return RedirectToAction(nameof(Index));
    }

    public IActionResult Index() => View();
}
```

**Principle**: skipping the `ModelState.IsValid` check lets a request that failed its data-annotation validation reach the persistence call anyway; check it first and return the input view (or a validation problem) so invalid data never reaches `SaveChangesAsync`.

**Layer note**: kit slices are minimal-API endpoints with no `ModelState`; validation there runs explicitly (e.g. a validator invoked before the handler), so this rule only fires if a module adds MVC-style controllers.
