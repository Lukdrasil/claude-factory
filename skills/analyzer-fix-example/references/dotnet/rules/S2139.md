# S2139: Exceptions should be either logged or rethrown but not both

**Analyzer**: SonarAnalyzer.CSharp · **Kit config**: not configured; on by default (Sonar way) · **Docs**: https://rules.sonarsource.com/csharp/RSPEC-2139/

## Wrong

```csharp
using Microsoft.Extensions.Logging;

namespace Kit.Payments.Features.CapturePayment;

internal sealed class CapturePaymentHandler(ILogger<CapturePaymentHandler> logger)
{
    public async Task HandleAsync(CapturePaymentCommand command, CancellationToken cancellationToken)
    {
        try
        {
            await CaptureAsync(command, cancellationToken);
        }
        catch (Exception ex)
        {
            logger.LogError(ex, "Capture failed for {PaymentId}", command.PaymentId); // logs
            throw; // Noncompliant: and rethrows the same exception
        }
    }

    private Task CaptureAsync(CapturePaymentCommand command, CancellationToken cancellationToken) =>
        Task.CompletedTask;
}

internal sealed record CapturePaymentCommand(Guid PaymentId);
```

## Right

```csharp
namespace Kit.Payments.Features.CapturePayment;

internal sealed class CapturePaymentHandler
{
    public Task HandleAsync(CapturePaymentCommand command, CancellationToken cancellationToken) =>
        CaptureAsync(command, cancellationToken);

    private Task CaptureAsync(CapturePaymentCommand command, CancellationToken cancellationToken) =>
        Task.CompletedTask;
}

internal sealed record CapturePaymentCommand(Guid PaymentId);
```

**Principle**: A logged-and-rethrown exception appears twice in the logs and pages two people for one failure; pick one owner for the report; let the boundary that actually handles the failure log it once.

**Layer note**: In a use case handler, let the exception propagate unlogged and have the single boundary that terminates the flow (the endpoint's exception middleware, or a top-level Infrastructure adapter) own the one log entry; logging inside every intermediate `catch` produces one log line per layer the exception passes through.
