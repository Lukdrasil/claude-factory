# CA2100: Review SQL queries for security vulnerabilities

**Analyzer**: Microsoft.CodeAnalysis.NetAnalyzers · **Kit config**: not configured; disabled by default; a dataflow/security rule that must be opted into via `<AnalysisMode>` (Recommended/All) or an explicit severity in `.editorconfig` · **Docs**: https://learn.microsoft.com/en-us/dotnet/fundamentals/code-analysis/quality-rules/ca2100

## Wrong

```csharp
using Microsoft.Data.SqlClient;

namespace Kit.Modules.Orders.Infrastructure.Persistence;

internal sealed class CustomerLookupRepository(SqlConnection connection)
{
    public async Task<int> FindCustomerIdAsync(string email, CancellationToken cancellationToken)
    {
        using var command = connection.CreateCommand();
        command.CommandText = "SELECT CustomerId FROM Customers WHERE Email = '" + email + "'"; // concatenated input
        return (int)await command.ExecuteScalarAsync(cancellationToken);
    }
}
```

## Right

```csharp
using Microsoft.Data.SqlClient;

namespace Kit.Modules.Orders.Infrastructure.Persistence;

internal sealed class CustomerLookupRepository(SqlConnection connection)
{
    public async Task<int> FindCustomerIdAsync(string email, CancellationToken cancellationToken)
    {
        using var command = connection.CreateCommand();
        command.CommandText = "SELECT CustomerId FROM Customers WHERE Email = @email";
        command.Parameters.Add(new SqlParameter("@email", SqlDbType.NVarChar, 256) { Value = email });
        return (int)await command.ExecuteScalarAsync(cancellationToken);
    }
}
```

**Principle**: A parameter placeholder sends the value to the database separately from the command text, so the database engine can never interpret user input as SQL syntax.

**Layer note**: Raw `SqlCommand` construction belongs only in Infrastructure persistence adapters; Application and Domain code should depend on a repository port and never build command text directly.
