# CA1826: Use property instead of Linq Enumerable method

**Analyzer**: Microsoft.CodeAnalysis.NetAnalyzers · **Kit config**: not configured; enabled by default as a suggestion (Info) in the .NET 10 SDK; an IDE-only hint, does not fail a warnings-as-errors build unless raised in `.editorconfig` · **Docs**: https://learn.microsoft.com/en-us/dotnet/fundamentals/code-analysis/quality-rules/ca1826

## Wrong

```csharp
namespace Kit.Modules.Orders.Application.Features.ReviewOrder;

internal sealed record OrderLine(string Sku, int Quantity);

internal sealed class OrderLineSummary
{
    public (OrderLine First, OrderLine Last, int Count) Summarize(IReadOnlyList<OrderLine> lines) =>
        (lines.First(), lines.Last(), lines.Count()); // Enumerable methods where indexer/Count already exist
}
```

## Right

```csharp
namespace Kit.Modules.Orders.Application.Features.ReviewOrder;

internal sealed record OrderLine(string Sku, int Quantity);

internal sealed class OrderLineSummary
{
    public (OrderLine First, OrderLine Last, int Count) Summarize(IReadOnlyList<OrderLine> lines) =>
        (lines[0], lines[^1], lines.Count);
}
```

**Principle**: An `IReadOnlyList<T>` already provides indexer and `Count` access in O(1), so calling the LINQ extension methods adds enumerator overhead for information the interface already exposes directly.
