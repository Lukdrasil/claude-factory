# CA1040: Avoid empty interfaces

**Analyzer**: Microsoft.CodeAnalysis.NetAnalyzers · **Kit config**: suggestion, in Ports folders · **Docs**: https://learn.microsoft.com/en-us/dotnet/fundamentals/code-analysis/quality-rules/ca1040

## Wrong

```csharp
namespace Kit.Modules.Billing.Application.Ports;

internal interface IBillingGatewayPort // no members: marker only
{
}
```

## Right

```csharp
namespace Kit.Modules.Billing.Application.Ports;

internal interface IBillingGatewayPort
{
    Task<PaymentResult> ChargeAsync(PaymentRequest request, CancellationToken ct);
}

internal sealed record PaymentRequest(Guid CustomerId, decimal Amount);
internal sealed record PaymentResult(bool Succeeded, string? ReferenceId);
```

**Principle**: A port exists to declare the operations an adapter must implement, so an interface with no members isn't a port at all; give it the operations it stands in for, or delete it.

**Layer note**: The kit enables CA1040 specifically for Application/Ports; an empty interface there provides no swappable contract for an Infrastructure adapter to fulfill. Marker interfaces elsewhere (e.g. compile-time capability tagging) are not flagged.
