# S7131: A write lock should not be released when a read lock has been acquired and vice versa

**Analyzer**: SonarAnalyzer.CSharp · **Kit config**: not configured; on by default (Sonar way) · **Docs**: https://rules.sonarsource.com/csharp/RSPEC-7131/

## Wrong

```csharp
namespace Kit.Catalog.Infrastructure.Caching;

internal sealed record ProductId(Guid Value);
internal sealed record Product(ProductId Id);

internal sealed class ProductCache
{
    private readonly ReaderWriterLockSlim _lock = new();
    private readonly Dictionary<ProductId, Product> _items = [];

    public Product? Find(ProductId id)
    {
        _lock.EnterReadLock();
        try
        {
            return _items.GetValueOrDefault(id);
        }
        finally
        {
            _lock.ExitWriteLock(); // Noncompliant: releases a write lock that was never acquired
        }
    }
}
```

## Right

```csharp
namespace Kit.Catalog.Infrastructure.Caching;

internal sealed record ProductId(Guid Value);
internal sealed record Product(ProductId Id);

internal sealed class ProductCache
{
    private readonly ReaderWriterLockSlim _lock = new();
    private readonly Dictionary<ProductId, Product> _items = [];

    public Product? Find(ProductId id)
    {
        _lock.EnterReadLock();
        try
        {
            return _items.GetValueOrDefault(id);
        }
        finally
        {
            _lock.ExitReadLock();
        }
    }
}
```

**Principle**: `ExitWriteLock()` on a lock entered with `EnterReadLock()` throws `LockRecursionException` (or, on the legacy `ReaderWriterLock`, corrupts lock ownership) because read and write ownership are tracked separately; always exit with the same read/write kind you entered with.
