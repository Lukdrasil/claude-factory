# MA0132: Do not convert implicitly to DateTimeOffset

**Analyzer**: Meziantou.Analyzer · **Kit config**: not configured; analyzer default: warning · **Docs**: https://github.com/meziantou/Meziantou.Analyzer/blob/main/docs/Rules/MA0132.md

## Wrong

```csharp
namespace Kit.Scheduling.Application.Features.CheckExpiry;

internal sealed class ExpiryChecker
{
    public TimeSpan TimeUntilExpiry(DateTime expiresAt, TimeProvider timeProvider)
        => expiresAt - timeProvider.GetUtcNow(); // MA0132: implicit DateTime -> DateTimeOffset conversion
}
```

## Right

```csharp
namespace Kit.Scheduling.Application.Features.CheckExpiry;

internal sealed class ExpiryChecker
{
    public TimeSpan TimeUntilExpiry(DateTimeOffset expiresAt, TimeProvider timeProvider)
        => expiresAt - timeProvider.GetUtcNow();
}
```

**Principle**: An implicit `DateTime` → `DateTimeOffset` conversion trusts `DateTime.Kind`, which is usually `Unspecified` and gets silently read as local time; taking `DateTimeOffset` at the boundary removes the ambiguous conversion instead of guessing an offset for it.

**Layer note**: The Application layer is where a boundary like this is fixed by tightening the contract type; the Domain must still receive the resolved timestamp as a plain parameter rather than pulling it from `TimeProvider` itself.
