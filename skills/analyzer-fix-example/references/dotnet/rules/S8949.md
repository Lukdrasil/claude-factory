# S8949: The overload accepting a 'CancellationToken' should be used

**Analyzer**: SonarAnalyzer.CSharp · **Kit config**: not configured; on by default (Sonar way) · **Docs**: https://rules.sonarsource.com/csharp/RSPEC-8949/

## Wrong

```csharp
using Microsoft.EntityFrameworkCore;

namespace Kit.Orders.Features.PlaceOrder;

internal sealed record Order(Guid Id);
internal sealed class OrderDbContext : DbContext { public DbSet<Order> Orders => Set<Order>(); }

internal sealed class PlaceOrderHandler(OrderDbContext dbContext)
{
    public async Task HandleAsync(Order order, CancellationToken cancellationToken)
    {
        dbContext.Orders.Add(order);
        await dbContext.SaveChangesAsync(); // Noncompliant: cancellationToken not forwarded
    }
}
```

## Right

```csharp
using Microsoft.EntityFrameworkCore;

namespace Kit.Orders.Features.PlaceOrder;

internal sealed record Order(Guid Id);
internal sealed class OrderDbContext : DbContext { public DbSet<Order> Orders => Set<Order>(); }

internal sealed class PlaceOrderHandler(OrderDbContext dbContext)
{
    public async Task HandleAsync(Order order, CancellationToken cancellationToken)
    {
        dbContext.Orders.Add(order);
        await dbContext.SaveChangesAsync(cancellationToken);
    }
}
```

**Principle**: an available `CancellationToken` that isn't forwarded to the overload accepting one means a caller's cancellation or request timeout is silently ignored by that call; always pass the token through to the overload that takes it.
