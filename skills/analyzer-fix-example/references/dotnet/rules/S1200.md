# S1200: Classes should not be coupled to too many other classes (Single Responsibility Principle)

**Analyzer**: SonarAnalyzer.CSharp · **Kit config**: warning in Domain; none in Infrastructure and tests · **Docs**: https://rules.sonarsource.com/csharp/RSPEC-1200/

## Wrong

```csharp
namespace Kit.Orders.Domain;

public sealed class Order // couples to too many other domain types
{
    private CustomerProfile _customer = null!;
    private ShippingAddress _address = null!;
    private BillingAddress _billing = null!;
    private DiscountPolicy _discount = null!;
    private TaxPolicy _tax = null!;
    private ShippingCarrier _carrier = null!;
    private LoyaltyAccount _loyalty = null!;

    public InvoiceDraft Compute(PricingContext context) =>
        new(_customer, _address, _billing, _discount, _tax, _carrier, _loyalty, context);
}
```

## Right

```csharp
namespace Kit.Orders.Domain;

public sealed class OrderParties
{
    public CustomerProfile Customer { get; }
    public ShippingAddress ShippingAddress { get; }
    public BillingAddress BillingAddress { get; }

    public OrderParties(CustomerProfile customer, ShippingAddress shippingAddress, BillingAddress billingAddress)
    {
        Customer = customer;
        ShippingAddress = shippingAddress;
        BillingAddress = billingAddress;
    }
}

public sealed class PricingPolicies
{
    public DiscountPolicy Discount { get; }
    public TaxPolicy Tax { get; }

    public PricingPolicies(DiscountPolicy discount, TaxPolicy tax)
    {
        Discount = discount;
        Tax = tax;
    }
}

public sealed class Order
{
    private OrderParties _parties = null!;
    private PricingPolicies _pricing = null!;

    public InvoiceDraft Compute(PricingContext context) => new(_parties, _pricing, context);
}
```

**Principle**: Seven collaborator types on one aggregate signal it is answering "who is this order for" and "how is it priced" at once; grouping the types that change together (parties, pricing policies) into their own collaborators lets `Order` depend on two cohesive things instead of seven scattered ones.

**Layer note**: This is a warning only in the Domain, where high coupling signals a class carrying multiple responsibilities; an Infrastructure adapter wiring several downstream clients together, or a test fixture composing many collaborators, is expected to touch many types and is exempt.
