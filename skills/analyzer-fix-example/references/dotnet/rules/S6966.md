# S6966: Awaitable method should be used

**Analyzer**: SonarAnalyzer.CSharp · **Kit config**: not configured; on by default (Sonar way) · **Docs**: https://rules.sonarsource.com/csharp/RSPEC-6966/

## Wrong

```csharp
using Microsoft.EntityFrameworkCore;

namespace Kit.Orders.Infrastructure;

internal sealed record OrderId(Guid Value);
internal sealed class Order { public OrderId Id { get; init; } = null!; }
internal sealed class OrderDbContext : DbContext { public DbSet<Order> Orders => Set<Order>(); }

internal sealed class OrderRepository(OrderDbContext dbContext)
{
    public async Task<Order?> FindAsync(OrderId id, CancellationToken cancellationToken)
    {
        return dbContext.Orders.FirstOrDefault(o => o.Id == id); // Noncompliant: blocks the thread
    }
}
```

## Right

```csharp
using Microsoft.EntityFrameworkCore;

namespace Kit.Orders.Infrastructure;

internal sealed record OrderId(Guid Value);
internal sealed class Order { public OrderId Id { get; init; } = null!; }
internal sealed class OrderDbContext : DbContext { public DbSet<Order> Orders => Set<Order>(); }

internal sealed class OrderRepository(OrderDbContext dbContext)
{
    public async Task<Order?> FindAsync(OrderId id, CancellationToken cancellationToken)
    {
        return await dbContext.Orders.FirstOrDefaultAsync(o => o.Id == id, cancellationToken);
    }
}
```

**Principle**: calling the synchronous `FirstOrDefault` inside an `async` method blocks the calling thread while EF Core executes the query, defeating the point of the async method and tying up a thread-pool thread under load; call the `*Async` counterpart and await it with the propagated `CancellationToken`.
