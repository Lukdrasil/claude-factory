# S4586: Non-async "Task/Task<T>" methods should not return null

**Analyzer**: SonarAnalyzer.CSharp · **Kit config**: not configured; on by default (Sonar way) · **Docs**: https://rules.sonarsource.com/csharp/RSPEC-4586/

## Wrong

```csharp
namespace Kit.Orders.Application.Ports;

internal sealed record OrderId(Guid Value);
internal sealed record Order(OrderId Id);

internal interface IOrderRepository
{
    Task<Order?> FindAsync(OrderId id, CancellationToken cancellationToken);
}

internal sealed class StubOrderRepository : IOrderRepository
{
    public Task<Order?> FindAsync(OrderId id, CancellationToken cancellationToken)
    {
        return null; // Task itself is null, not a Task<Order?> wrapping null
    }
}
```

## Right

```csharp
namespace Kit.Orders.Application.Ports;

internal sealed record OrderId(Guid Value);
internal sealed record Order(OrderId Id);

internal interface IOrderRepository
{
    Task<Order?> FindAsync(OrderId id, CancellationToken cancellationToken);
}

internal sealed class StubOrderRepository : IOrderRepository
{
    public Task<Order?> FindAsync(OrderId id, CancellationToken cancellationToken)
    {
        return Task.FromResult<Order?>(null);
    }
}
```

**Principle**: A non-async Task-returning method that returns the null reference itself throws a NullReferenceException the instant a caller awaits it; return `Task.FromResult(null)` (or `Task.CompletedTask` for non-generic `Task`) so the Task instance always exists even when the payload doesn't.
