# CA1852: Seal internal types

**Analyzer**: Microsoft.CodeAnalysis.NetAnalyzers · **Kit config**: not configured; not enabled by default; requires `<AnalysisMode>Recommended</AnalysisMode>` (or higher) or an explicit severity in `.editorconfig` · **Docs**: https://learn.microsoft.com/en-us/dotnet/fundamentals/code-analysis/quality-rules/ca1852

## Wrong

```csharp
namespace Kit.Modules.Orders.Application.Features.CancelOrder;

internal sealed record CancelOrderCommand(Guid OrderId);

internal interface IOrderRepository
{
    Task CancelAsync(Guid orderId, CancellationToken cancellationToken);
}

internal class CancelOrderHandler(IOrderRepository repository) // not sealed - analyzer fires here
{
    public Task HandleAsync(CancelOrderCommand command, CancellationToken cancellationToken) =>
        repository.CancelAsync(command.OrderId, cancellationToken);
}
```

## Right

```csharp
namespace Kit.Modules.Orders.Application.Features.CancelOrder;

internal sealed record CancelOrderCommand(Guid OrderId);

internal interface IOrderRepository
{
    Task CancelAsync(Guid orderId, CancellationToken cancellationToken);
}

internal sealed class CancelOrderHandler(IOrderRepository repository)
{
    public Task HandleAsync(CancelOrderCommand command, CancellationToken cancellationToken) =>
        repository.CancelAsync(command.OrderId, cancellationToken);
}
```

**Principle**: A type with no subtypes anywhere in its assembly gains no polymorphism from being unsealed, so sealing it lets the JIT devirtualize its member calls and inline more aggressively.
