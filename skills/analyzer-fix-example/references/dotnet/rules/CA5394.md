# CA5394: Do not use insecure randomness

**Analyzer**: Microsoft.CodeAnalysis.NetAnalyzers · **Kit config**: not configured; disabled by default; must be opted into via `<AnalysisMode>` (Recommended/All) or an explicit severity in `.editorconfig` · **Docs**: https://learn.microsoft.com/en-us/dotnet/fundamentals/code-analysis/quality-rules/ca5394

## Wrong

```csharp
namespace Kit.Modules.Orders.Application.Features.RequestPasswordReset;

internal sealed class PasswordResetCodeGenerator
{
    private readonly Random _random = new(); // insecure PRNG feeding a security-sensitive value

    public string Generate() => _random.Next(100_000, 999_999).ToString();
}
```

## Right

```csharp
using System.Security.Cryptography;

namespace Kit.Modules.Orders.Application.Features.RequestPasswordReset;

internal sealed class PasswordResetCodeGenerator
{
    public string Generate() => RandomNumberGenerator.GetInt32(100_000, 999_999).ToString();
}
```

**Principle**: A cryptographically secure generator makes each value unpredictable even to an attacker who has observed prior outputs, whereas `System.Random`'s algorithm is deterministic and can be reconstructed from a handful of samples.
