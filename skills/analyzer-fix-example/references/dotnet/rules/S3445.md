# S3445: Exceptions should not be explicitly rethrown

**Analyzer**: SonarAnalyzer.CSharp · **Kit config**: not configured; on by default (Sonar way) · **Docs**: https://rules.sonarsource.com/csharp/RSPEC-3445/

## Wrong

```csharp
namespace Kit.Orders.Application.Features.PlaceOrder;

internal sealed class PlaceOrderHandler
{
    public async Task<Guid> HandleAsync(PlaceOrderCommand command, CancellationToken cancellationToken)
    {
        try
        {
            return await SubmitAsync(command, cancellationToken);
        }
        catch (InvalidOperationException ex)
        {
            throw ex; // Noncompliant: clears the original stack trace
        }
    }

    private static Task<Guid> SubmitAsync(PlaceOrderCommand command, CancellationToken cancellationToken) =>
        Task.FromResult(Guid.NewGuid());
}

internal sealed record PlaceOrderCommand(int Quantity, decimal UnitPrice);
```

## Right

```csharp
namespace Kit.Orders.Application.Features.PlaceOrder;

internal sealed class PlaceOrderHandler
{
    public async Task<Guid> HandleAsync(PlaceOrderCommand command, CancellationToken cancellationToken)
    {
        try
        {
            return await SubmitAsync(command, cancellationToken);
        }
        catch (InvalidOperationException)
        {
            throw;
        }
    }

    private static Task<Guid> SubmitAsync(PlaceOrderCommand command, CancellationToken cancellationToken) =>
        Task.FromResult(Guid.NewGuid());
}

internal sealed record PlaceOrderCommand(int Quantity, decimal UnitPrice);
```

**Principle**: `throw;` preserves the call stack captured at the original throw site, while `throw ex;` resets it to the catch block, hiding where the failure actually originated.
