# CA3001: Review code for SQL injection vulnerabilities

**Analyzer**: Microsoft.CodeAnalysis.NetAnalyzers · **Kit config**: not configured; disabled by default; a dataflow/security rule that must be opted into via `<AnalysisMode>` (Recommended/All) or an explicit severity in `.editorconfig` · **Docs**: https://learn.microsoft.com/en-us/dotnet/fundamentals/code-analysis/quality-rules/ca3001

## Wrong

```csharp
using Microsoft.EntityFrameworkCore;

namespace Kit.Modules.Orders.Infrastructure.Persistence;

internal sealed class Product { public int Id { get; set; } public string Name { get; set; } = ""; }

internal sealed class OrdersDbContext : DbContext
{
    public DbSet<Product> Products => Set<Product>();
}

internal sealed record ProductDto(int Id, string Name);

internal sealed class ProductSearchRepository(OrdersDbContext dbContext)
{
    public Task<List<ProductDto>> SearchByNameAsync(string name, CancellationToken cancellationToken) =>
        dbContext.Products
            .FromSqlRaw($"SELECT * FROM Products WHERE Name = '{name}'") // interpolated raw SQL
            .Select(p => new ProductDto(p.Id, p.Name))
            .ToListAsync(cancellationToken);
}
```

## Right

```csharp
using Microsoft.EntityFrameworkCore;

namespace Kit.Modules.Orders.Infrastructure.Persistence;

internal sealed class Product { public int Id { get; set; } public string Name { get; set; } = ""; }

internal sealed class OrdersDbContext : DbContext
{
    public DbSet<Product> Products => Set<Product>();
}

internal sealed record ProductDto(int Id, string Name);

internal sealed class ProductSearchRepository(OrdersDbContext dbContext)
{
    public Task<List<ProductDto>> SearchByNameAsync(string name, CancellationToken cancellationToken) =>
        dbContext.Products
            .Where(p => p.Name == name)
            .Select(p => new ProductDto(p.Id, p.Name))
            .ToListAsync(cancellationToken);
}
```

**Principle**: Building the query as LINQ straight against `DbSet<T>` lets EF Core parameterize the generated SQL itself, removing both the injection surface and the need to hand-write SQL at all.

**Layer note**: `DbContext` and query construction stay in Infrastructure persistence adapters; Application and Domain code depend only on the repository port that wraps this repository.
