# S3998: Threads should not lock on objects with weak identity

**Analyzer**: SonarAnalyzer.CSharp · **Kit config**: not configured; on by default (Sonar way) · **Docs**: https://rules.sonarsource.com/csharp/RSPEC-3998/

## Wrong

```csharp
namespace Kit.Catalog.Infrastructure;

internal sealed class CatalogCache
{
    private readonly Dictionary<string, decimal> _prices = [];

    public void SetPrice(string sku, decimal price)
    {
        lock (sku) // Noncompliant: string has weak identity; it can be interned and shared
        {
            _prices[sku] = price;
        }
    }
}
```

## Right

```csharp
namespace Kit.Catalog.Infrastructure;

internal sealed class CatalogCache
{
    private readonly Dictionary<string, decimal> _prices = [];
    private readonly Lock _gate = new();

    public void SetPrice(string sku, decimal price)
    {
        lock (_gate)
        {
            _prices[sku] = price;
        }
    }
}
```

**Principle**: locking on a string risks blocking on unrelated code that happens to hold the same interned value anywhere in the process; a dedicated private `Lock` field guarantees the lock guards only this cache's own critical section.
