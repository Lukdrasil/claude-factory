# S3776: Cognitive Complexity of methods should not be too high

**Analyzer**: SonarAnalyzer.CSharp · **Kit config**: warning in Domain and Features; none in tests · **Docs**: https://rules.sonarsource.com/csharp/RSPEC-3776/

## Wrong

```csharp
namespace Kit.Orders.Domain;

public sealed class Order
{
    private OrderStatus _status;
    private readonly List<OrderLine> _lines = [];

    public decimal CalculateShippingCost(bool isExpress, bool isFragile) // cognitive complexity
    {
        decimal cost;
        if (_status == OrderStatus.Cancelled)
        {
            cost = 0m;
        }
        else
        {
            if (isExpress)
            {
                if (isFragile)
                    cost = 25m;
                else
                    cost = 15m;
            }
            else
            {
                if (isFragile)
                    cost = 10m;
                else
                    cost = 5m;
            }
        }
        return cost;
    }
}
```

## Right

```csharp
namespace Kit.Orders.Domain;

public sealed class Order
{
    private OrderStatus _status;
    private readonly List<OrderLine> _lines = [];

    public decimal CalculateShippingCost(bool isExpress, bool isFragile)
    {
        if (_status == OrderStatus.Cancelled)
            return 0m;

        return (isExpress, isFragile) switch
        {
            (true, true) => 25m,
            (true, false) => 15m,
            (false, true) => 10m,
            (false, false) => 5m,
        };
    }
}
```

**Principle**: Each nested `if` forces the reader to hold the outer branch in mind while evaluating the inner one; an early guard clause for the terminal case plus a pattern-matching switch over the remaining combinations flattens the control flow to one level.

**Layer note**: Enforced in Domain and Features because branching business rules belong there; test methods are exempt since arranging several scenarios in one test naturally raises branch count without indicating a design problem.
