# MA0042: Do not use blocking calls when the calling method is async

**Analyzer**: Meziantou.Analyzer · **Kit config**: not configured; analyzer default: Info · **Docs**: https://github.com/meziantou/Meziantou.Analyzer/blob/main/docs/Rules/MA0042.md

## Wrong

```csharp
namespace Kit.Notifications.Application.Features.SendEmail;

internal interface IEmailClient
{
    Task SendAsync(string to, string body, CancellationToken cancellationToken);
}

internal sealed class EmailSender(IEmailClient client)
{
    public async Task SendAsync(string to, string body, CancellationToken cancellationToken)
    {
        client.SendAsync(to, body, cancellationToken).Wait(); // MA0042: blocking call in async method
    }
}
```

## Right

```csharp
namespace Kit.Notifications.Application.Features.SendEmail;

internal interface IEmailClient
{
    Task SendAsync(string to, string body, CancellationToken cancellationToken);
}

internal sealed class EmailSender(IEmailClient client)
{
    public async Task SendAsync(string to, string body, CancellationToken cancellationToken)
    {
        await client.SendAsync(to, body, cancellationToken);
    }
}
```

**Principle**: Wait() blocks the calling thread until the inner task completes, which can deadlock a caller bound to a synchronization context and always ties up a pooled thread for no reason; await releases the thread back to the pool until the send genuinely finishes.
