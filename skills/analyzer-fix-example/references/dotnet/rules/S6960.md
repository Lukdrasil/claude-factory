# S6960: Controllers should not have mixed responsibilities

**Analyzer**: SonarAnalyzer.CSharp · **Kit config**: not configured; on by default (Sonar way) · **Docs**: https://rules.sonarsource.com/csharp/RSPEC-6960/

## Wrong

```csharp
namespace Kit.Media.Controllers;

internal interface IStreamingService { Stream GetStream(Guid movieId); }
internal interface IPhotoEnhancementService { Stream Enhance(Guid photoId); }

[ApiController]
[Route("media")]
internal sealed class MediaController(IStreamingService streaming, IPhotoEnhancementService photoEnhancement)
    : ControllerBase // Noncompliant: mixes video-streaming and photo-editing concerns
{
    [HttpGet("movie/stream")]
    public IActionResult MovieStream(Guid movieId) => File(streaming.GetStream(movieId), "video/mp4");

    [HttpPost("photo/enhance")]
    public IActionResult EnhancePhoto(Guid photoId) => File(photoEnhancement.Enhance(photoId), "image/jpeg");
}
```

## Right

```csharp
namespace Kit.Media.Controllers;

internal interface IStreamingService { Stream GetStream(Guid movieId); }
internal interface IPhotoEnhancementService { Stream Enhance(Guid photoId); }

[ApiController]
[Route("media/movies")]
internal sealed class MovieController(IStreamingService streaming) : ControllerBase
{
    [HttpGet("stream")]
    public IActionResult Stream(Guid movieId) => File(streaming.GetStream(movieId), "video/mp4");
}

[ApiController]
[Route("media/photos")]
internal sealed class PhotoController(IPhotoEnhancementService photoEnhancement) : ControllerBase
{
    [HttpPost("enhance")]
    public IActionResult Enhance(Guid photoId) => File(photoEnhancement.Enhance(photoId), "image/jpeg");
}
```

**Principle**: one controller routing both video-streaming and photo-editing endpoints forces every consumer of the class, and every test of it, to depend on both services; splitting by the resource each action owns keeps each controller's dependency list to one concern.

**Layer note**: kit vertical slices are minimal-API endpoints, one file per use case, so there's no controller to mix responsibilities on in the first place; this rule only becomes relevant if a module adds MVC-style controllers, e.g. for legacy interop.
