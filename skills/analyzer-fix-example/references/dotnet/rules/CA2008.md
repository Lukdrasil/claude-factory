# CA2008: Do not create tasks without passing a TaskScheduler

**Analyzer**: Microsoft.CodeAnalysis.NetAnalyzers · **Kit config**: not configured, off by default; enable via dotnet_diagnostic.CA2008.severity = warning · **Docs**: https://learn.microsoft.com/en-us/dotnet/fundamentals/code-analysis/quality-rules/ca2008

## Wrong

```csharp
namespace Infrastructure.Jobs;

internal sealed class ReportWarmupJob
{
    public void ScheduleWarmup(CancellationToken cancellationToken)
    {
        Task.Factory.StartNew(() => WarmupAsync(cancellationToken)); // CA2008: no TaskScheduler passed
    }

    private static Task WarmupAsync(CancellationToken cancellationToken) => Task.CompletedTask;
}
```

## Right

```csharp
namespace Infrastructure.Jobs;

internal sealed class ReportWarmupJob
{
    public void ScheduleWarmup(CancellationToken cancellationToken)
    {
        Task.Factory.StartNew(
            () => WarmupAsync(cancellationToken),
            cancellationToken,
            TaskCreationOptions.None,
            TaskScheduler.Default);
    }

    private static Task WarmupAsync(CancellationToken cancellationToken) => Task.CompletedTask;
}
```

**Principle**: Passing `TaskScheduler.Default` explicitly means the job always runs on the thread pool, instead of silently inheriting whatever scheduler happens to be current on the calling thread.
