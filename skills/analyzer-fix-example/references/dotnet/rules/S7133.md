# S7133: Locks should be released within the same method

**Analyzer**: SonarAnalyzer.CSharp · **Kit config**: not configured; on by default (Sonar way) · **Docs**: https://rules.sonarsource.com/csharp/RSPEC-7133/

## Wrong

```csharp
namespace Kit.Catalog.Infrastructure.Caching;

internal sealed record Product(Guid Id);

internal sealed class ProductCache
{
    private readonly ReaderWriterLockSlim _lock = new();

    public void BeginWrite() => _lock.EnterWriteLock(); // Noncompliant: acquired here, released elsewhere

    public void Update(Product product)
    {
        // mutate cache
    }

    public void EndWrite() => _lock.ExitWriteLock();
}
```

## Right

```csharp
namespace Kit.Catalog.Infrastructure.Caching;

internal sealed record Product(Guid Id);

internal sealed class ProductCache
{
    private readonly ReaderWriterLockSlim _lock = new();

    public void Update(Product product)
    {
        _lock.EnterWriteLock();
        try
        {
            // mutate cache
        }
        finally
        {
            _lock.ExitWriteLock();
        }
    }
}
```

**Principle**: splitting acquire and release across separate public methods lets a caller invoke them out of order, skip the release, or leak the lock when an exception is thrown between the two calls; acquire and release inside one method wrapped in try/finally.
