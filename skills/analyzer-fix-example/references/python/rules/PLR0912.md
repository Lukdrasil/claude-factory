# PLR0912: too-many-branches

**Tool**: Ruff (Pylint) · **Kit config**: in kit `extend-select` ("PL" group); limit 12 via `[lint.pylint] max-branches` · **Docs**: https://docs.astral.sh/ruff/rules/too-many-branches/

## Wrong

```python
def classify(n: int) -> str:
    if n == 0:
        return "zero"
    elif n == 1:
        return "one"
    elif n == 2:
        return "two"
    elif n == 3:
        return "three"
    elif n == 4:
        return "four"
    elif n == 5:
        return "five"
    elif n == 6:
        return "six"
    elif n == 7:
        return "seven"
    elif n == 8:
        return "eight"
    elif n == 9:
        return "nine"
    elif n == 10:
        return "ten"
    elif n == 11:
        return "eleven"
    elif n == 12:
        return "twelve"
    else:
        return "other"
```

## Right

```python
_NUMBER_NAMES = {
    0: "zero", 1: "one", 2: "two", 3: "three", 4: "four",
    5: "five", 6: "six", 7: "seven", 8: "eight", 9: "nine",
    10: "ten", 11: "eleven", 12: "twelve",
}


def classify(n: int) -> str:
    return _NUMBER_NAMES.get(n, "other")
```

**Principle**: a lookup table turns a linear chain of branches, each one a place a bug can hide, into a single O(1) data access, and the mapping is what the logic actually was.
